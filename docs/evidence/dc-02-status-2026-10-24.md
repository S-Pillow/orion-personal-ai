## Lifecycle / harness finding

A full-Orion model-headroom preflight exposed a shutdown-lifecycle issue:

- prestate contained zero Ollama-family processes;
- the test started Orion normally;
- `Stop-Orion.ps1` reported `Owned Ollama: stopped`;
- a new `llama-server.exe` process remained afterward;
- the residual process was PID `34076` for that observed run;
- a later bounded cleanup validated that PID as the test-owned model server and terminated it;
- subsequent GPU diagnostic cleanup returned the workstation to clean manual-off.

This is evidence that normal Orion/Ollama shutdown can leave a child `llama-server.exe` behind. Treat this as a lifecycle follow-up; it is separate from DC-02 retrieval implementation correctness.

Test harnesses must independently guarantee clean poststate rather than treating normal operator shutdown as sufficient. A test must not report overall PASS when its own poststate manual-off check fails.
